# Security remediation log

Tracks the status of every finding from `SECURITY-AUDIT-2026-08-21.md`, re-verified against this fork (`kingdom-connections`) per the plan in this session. One row per finding. Status values: **Fixed**, **Deferred**, **Human action required**, **Not applicable**, **Not started**.

Test scripts live in `server/tests/security/`, one file per finding, runnable standalone via `node server/tests/security/<file>.test.js`. Each was written and run against the *unpatched* code first (via `git stash` on just the relevant file) to empirically confirm it fails before the fix, then re-run after restoring the fix to confirm it passes — per the audit's own methodology requirement.

## Phase 5 — Adversarial retest (complete)

Full write-up in `Security Review/PHASE5-ADVERSARIAL-RETEST.md`. Summary:

- **Rebuilt the route-authorization-coverage check as a standing test** (`server/tests/security/PHASE5-00.route-coverage.test.js`) — statically enumerates all 523 routes across every mounted router, classifying each as protected, explicitly public (documented allowlist), or unknown. - **That very first run found a real, previously-unknown vulnerability**: `GET /api/ada/check` (an accessibility checker) was completely unauthenticated and fetched any caller-supplied URL server-side with no restriction — a full SSRF primitive reachable by anyone on the internet, confirmed live against the server's own loopback address. Fixed with `requireAuth` + `requirePermission('settings.manage')` plus a new shared `services/urlSafety.js` (`isSafeTargetUrl()`) that resolves the hostname via DNS and blocks private/loopback/link-local ranges.

- Every fix from Phases 0–4 was attacked directly (path-traversal encoding variants, AI tool deny-by-default, TOTP window strictness) and held. Section 6's "sound" controls were all re-confirmed intact.
